# 專案存取與章節樹修復

章節與資料夾的新 ID 使用 UUID。載入、更新章節狀態與建立儲存快照時，會替空白或重複 ID 分配新值，保留所有章節正文及資料夾，並重建直接子項目順序。有效且未重複的 ID 保持不變。重複 ID 原有的外部參照無法判斷屬於哪個節點，修復會保留首次出現的 ID，不猜測參照的歸屬。

專案 I/O 失敗後，工具列、快捷鍵與編輯器不再沿用 Riverpod 保留的忙碌狀態。變更仍留在編輯器，可重試儲存或另存新檔。

macOS 最近檔案會優先使用持久書籤開啟；手動儲存及自動儲存都在有效的 security scope 內寫入。過期但可解析的書籤會更新並保存回最近檔案。Debug/Profile 與 Release 均啟用 app-scoped bookmark entitlement。

跨版本更新測試需使用相同 Bundle ID、相同開發團隊的有效簽章。專案目前的本機建置設定包含 ad hoc 簽章（`CODE_SIGN_IDENTITY = "-"`）；不同建置的簽章身分不保證連續，無法據此保證 macOS 保留授權。程式無法恢復已被系統撤銷、從未保存或無法解析的書籤，這種情況仍須重新選取一次原檔案。

發佈前實機驗證：

1. 在沙箱版本 A 開啟 Documents 內的專案並儲存，完全退出程式。
2. 以相同簽章身分安裝版本 B，從最近檔案開啟、修改、手動儲存及等待自動儲存，確認不需重新選檔。
3. 移動原檔案後重開，確認可解析的書籤更新路徑且儲存成功。
4. 在可丟棄的副本上撤銷檔案權限，確認錯誤對話框關閉後仍能編輯、重試及另存新檔。

Ribbon 的展開大按鈕預設自動換行，最多兩行並保留完整 tooltip。可在 `RibbonCommand` 設定 `wrapLargeLabel: false` 恢復單行；緊湊模式維持單行。
